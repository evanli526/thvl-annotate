# THVL-Bench 标注：clone 后运行，从这里开始

欢迎参与 THVL-Bench。你的任务是查看视频，核对机器预标注，修正类别和起止时间、删除误报、补充漏报，并写明判断依据。

**启动方式就是三步：克隆仓库 → 运行 Python → 打开本地网页。无需标注网站账号密码，也不用事先向管理员索取网页地址。** 视频保存在云端，播放时按需读取；不会把约 18 GB 的数据集整体下载到电脑。

本文说明“怎么开始和怎么操作”；类别与边界判据请阅读[标注规范（instructions.md）](instructions.md)。

## 一、准备必要内容

你需要：**Python 3.10 或更新版本、Git、Chrome 或 Edge，以及能正常播放云端视频的网络。** 不需要 GPU，也不用安装任何 Python 第三方库。使用耳机，确认电脑与浏览器没有静音。

在终端中检查：

```bash
python --version
git --version
```

如果显示找不到命令，请先从 Python 或 Git 的官方网站安装；Windows 安装 Python 时勾选“Add Python to PATH”。macOS/Linux 通常使用 `python3`，下文的 `python` 可相应替换。

从负责人处只需确认**你的工作代号（A1、A2 或 EXPERT）和任务范围**。代号用于区分本机保存目录，不是账号密码，也与风险类别 A1/A2 无关。

## 二、三步开始

### 第一步：克隆仓库

在希望存放标注工作的目录打开终端，执行：

```bash
git clone https://github.com/evanli526/thvl-annotate.git
cd thvl-annotate
```

仓库包含界面、启动脚本和约 6.4 MB 的压缩标注包，不包含视频文件。包内已有 450 条任务、11,482 条机器建议和转写，无需自己生成任务。

这是独立标注仓库，由负责人完成首次发布后使用；研究主仓库不需要公开。如果已经克隆过这个独立仓库，先进入原来的目录，执行 `git pull --ff-only` 获取更新。不要为更新程序而删除原目录；你的人工结果也保存在其中。如果 Git 提示仓库不存在，请联系负责人确认独立仓库已经发布、地址是否正确。

### 第二步：运行 Python

```bash
python annotate.py
```

按终端提示输入自己的代号，例如 `A1`，按回车。脚本会准备任务、显示结果保存位置，并尝试自动打开浏览器。

也可以一次指定代号，适合以后重复启动：

```bash
python annotate.py --annotator A1
```

第二位标注员将 `A1` 改为 `A2`；专家改为 `EXPERT`。**请保持这个终端运行，关闭它会停止本机网页服务。**

### 第三步：打开脚本打印的网页

浏览器通常会自动打开。若没有，请复制终端中“浏览器地址”后面的完整地址，例如：

```text
http://127.0.0.1:8800/?annotator=A1
```

这个地址由你刚启动的程序提供，不是需要另行领取的公网链接。端口被占用时程序会自动选择另一个端口，以终端实际输出为准。不要直接双击 `annotate.html`。

进入后，确认顶部代号正确、左侧出现视频任务。选择分配给你的视频，试播几秒，检查画面、声音和进度拖动，然后开始第四部分的标注步骤。

**网页在本机，视频在云端，人工结果保存在你的电脑。** 播放仍需要联网，首次缓冲可能较慢。不要两个人共用同一代号；本地版本允许切换代号，不能把代号当访问权限保护。两人各自在自己的电脑上独立标注即可。

## 三、认识工作台：先找到这四个区域

| 区域 | 你会看到什么 | 主要用途 |
|---|---|---|
| 左侧“视频任务” | 视频编号、时长、进度和筛选按钮 | 找到分配的视频，切换到下一条 |
| 中间播放器与时间轴 | 视频、倍速、前后定位按钮、转写 | 看完整上下文，定位证据发生时刻 |
| “机器预标注建议”与“机器待检查区间” | 机器标签、理由、原始区间，以及需要补查的位置 | 帮助发现问题；它们不等于已确认答案 |
| 右侧“事件片段”与视频结论 | 可编辑的起止时间、标签、模态、理由和状态 | 填写并保存你自己的标注 |

**机器建议和你的标注是两份记录。** 初次打开任务时，机器片段会作为人工草稿的起点；你修改或删除右侧片段，不会删除原始机器建议。再次进入已有任务时，应继续自己的已保存结果。

机器置信度高也可能判断错误，标为 `ok` 也不表示人工已确认。`partial` 表示机器结果不完整，不能解释为对应位置安全。即使没有机器候选，也要检查完整视频。

### 常用播放操作

| 想做什么 | 如何操作 |
|---|---|
| 播放或暂停 | 点击播放器按钮，或按空格 |
| 初步了解全片 | 按理解程度选择 1×、1.25×、1.5× 或 2×；听不清、动作太快时降速 |
| 看清关键动作或边界 | 使用 0.5× 或 0.75×，必要时暂停反复看 |
| 前后找位置 | 点击 `−1s / +1s / −5s / +5s` |
| 小幅调整画面位置 | 暂停后按 `,` 或 `.`，每次微调 0.1 秒；这不是逐帧移动 |
| 反复看一个已选片段 | 点击“播放本段”或“循环本段”；按 Esc 退出循环 |
| 查其他快捷键 | 点击顶部“快捷键” |

倍速只改变播放速度，**所有标注时间仍填写原视频的秒数**。例如 `01:35` 应填 `95`，不能填成 `1.35`。3× 可用于寻找已知位置，不宜用来代替难懂语音或快速动作的认真核查。

## 四、标注员：每条视频按这六步完成

### 第一步：完整观看，留意机器没标出的内容

从头到尾查看画面并听音，了解人物、事件和说话语境。不要只点击机器框出的几秒钟，也不要仅阅读转写就跳过原视频。

看到疑似漏报的位置，可以先暂停并记下时间，随后补标。因缺媒体、缺音频或其他问题没有看完时，**不要勾选“我已完整查看本视频并检查机器漏报”**。

### 第二步：逐条核对右侧的“事件片段”

选择一个片段，点击“播放本段”；需要时向前、向后多看一些上下文，再决定如何处理。

| 你看到的情况 | 应当怎么做 |
|---|---|
| 类别和内容成立 | 修正起止时间、证据模态和理由；确认后取消该片段的“待复核”勾选 |
| 只有部分标签成立 | 取消缺乏依据的标签，保留成立标签，并重写对应理由 |
| 整个片段是误报 | 点击“删除 [Del]”；不要保留一个没有标签的空壳片段 |
| 同一行为被重复切开 | 判断是否确实连续；可保留一条、调整其边界，再删除重复条目 |
| 一条片段跨过明显正常间隔 | 将两段风险分别标注；不要把正常间隔一起框成风险 |
| 看完仍不能确定 | 保留有具体依据的疑似片段，勾选“待复核（证据不足，交专家）”，在理由或备注中写出具体疑问 |

**不要为了减少条数而强行合并，也不要为了通过检查就批量取消“待复核”。** 当前机器片段比较细，但最终应按完整语义和实际证据划分，不以每视频必须有几段为目标。

### 第三步：补充漏报，填写完整信息

发现没有被标出的风险时：

1. 将视频暂停在风险开始的位置，点击“＋ 新建片段”。
2. 在“起点（秒）”旁点击“取播放头 [”，或直接输入时间。
3. 播放到风险结束的位置，在“终点（秒）”旁点击“取播放头 ]”，或直接输入时间。
4. 检查起点小于终点，且两者都在视频范围内；用“播放本段”确认边界。
5. 选择成立的二级风险标签，再选择证据模态。
6. 填写一句具体理由；证据仍不够时保留“待复核”。

界面中的三种证据模态分别是：

- **视频**：画面中的动作、物体或可见内容支持判断。
- **语音/字幕语义**：实际听到的话或看到的字幕含义支持判断。自动转写可能出错，应与原音核对。
- **环境音**：撞击、爆炸、叫喊等非语言声音支持判断。不能因为视频“有声音”就勾选。

例如，确认 95–99 秒有人持棍击打他人，可以填写：起点 `95`、终点 `99`、标签 `A1 暴力攻击`、模态“视频”，理由“画面中男子持棍击打另一人的背部”。时间只是操作示例，应以当前视频实际证据为准。

理由要回答“看到了什么或听到了什么”，避免只写“有风险”“模型判断正确”。涉及事实核查、授权或目的等依据，可在“核验材料”中补充；拿不准时说明缺少什么，不要编造条件。

### 第四步：逐项处理“机器待检查区间”

点击“查看机器待检查区间”，逐项回看对应位置，并在下拉框中选择处理结果。

| 选项 | 什么时候使用 |
|---|---|
| 已查看 | 已核查该问题，现有标注已覆盖或无需进一步修改 |
| 已补标 | 因该提示发现漏报，且已在右侧真正新增相应片段 |
| 确认不成立 | 已核查，提示中的风险缺少成立依据 |
| 仍存疑，交专家 | 缺少必要证据、媒体不可用或看后仍不能判断 |

**选择“已补标”不会自动生成片段；选择“确认不成立”也不会自动删除右侧片段。** 请先完成相应编辑，再记录处理结果。提交视频结论前，不要留下“待处理”项。

如果提示的是“候选可能错位或未落实”，请重点核对所提示的事件是否确实出现在那个时间段，不要用附近另一段同类事件代替。

### 第五步：给出视频级结论

完成片段和复核队列后，再选择视频状态：

| 状态 | 使用条件 |
|---|---|
| 进行中 | 尚未检查完，或准备暂时离开；保留草稿继续处理 |
| 已完成 | 已完整查看，至少保留一个成立的风险片段，且没有未解决的疑问 |
| 确认无风险内容 | 已完整查看，所有风险候选均不成立，右侧风险片段已全部删除 |
| 需专家复核 | 有未解决的类别、证据或边界问题，或媒体不完整而无法作出结论 |

确实看完后，勾选“我已完整查看本视频并检查机器漏报”。选择“已完成”或“确认无风险内容”时，这一项必须勾选。

如果未能看完，应保留未勾选状态并说明原因；必要时选择“需专家复核”，将相关队列项设为“仍存疑，交专家”。“没有看见风险”和“没有条件看完整视频”是不同结论。

### 第六步：确认保存，再切换下一条

修改会自动保存，也可按 `Ctrl+S`（Mac 为 `⌘+S`）立即触发保存。**界面没有另一个必须点击的“提交”按钮：选择视频结论并成功保存，就提交了该状态。**

离开前确认：

- 本视频该检查的内容已经处理，状态与实际进度一致。
- 保留的每段都有正确时间、至少一个标签、证据模态和具体理由。
- 需要专家处理的问题已写清楚，复核队列没有漏选处理结果。
- 页面顶部显示“已保存”，没有错误或冲突提示。

然后点击“下一个”，或从左侧选择下一条分配的视频。只看到自己已经改完，还不等于本机文件已经保存成功。

## 五、专家：从两份人工结果到最终裁决

开始前，请收齐两位标注员交回的结果文件夹，将 `A1` 和 `A2` 放到你这份仓库的 `.annotation-work/desktop-quality_review_20260914/annotations/` 下，保留内部目录结构。若已有同名结果，先备份并确认哪份更新，不要直接覆盖。三人应使用同一任务版本；不要手动修改版本字段来绕过检查。

然后运行 `python annotate.py --annotator EXPERT`，打开程序打印的本地网页。不同电脑不会自动同步人工结果；只有拷入同一工作目录后，专家才能对照两份记录。

### 第一步：进入 EXPERT 工作区，检查两人是否已提交

进入 EXPERT 工作区，选择待核验视频，查看专家区域中的 A1、A2 状态和备注。

如果任一人尚未提交或仍为“进行中”，可以先查看问题、保存专家草稿，但**不能完成最终核验**。两位标注员可以将无法解决的情况以“需专家复核”提交，不必强行改成“已完成”。

### 第二步：对照差异，并回看原视频

界面会显示两份片段及时间重叠对比。重点检查：一人标了而另一人没标的内容、类别不同、起止时间不同，以及两人都留下的疑问。

不要仅凭两人一致或重叠百分比较高就接受结果；两人看到相同机器建议，可能共同接受误报或共同遗漏风险。专家仍需完整复看视频并听音，检查未标区域。页面上的重叠度只是局部区间对比，不是整体标注质量分数。

### 第三步：选择起稿，逐段作出裁决

如某一人的标注适合作为基础，点击“以 A1 的片段作为本次裁决起稿”或对应 A2 按钮。

该操作会替换**当前专家草稿中的片段**，不会覆盖两份人工原件。若已经精修过专家草稿，切换起稿前先备份，避免丢失本轮修改。

随后使用与标注员相同的编辑方法，保留正确内容、修改错类、精修边界、合并重复、拆开正常间隔，并补充漏报。每个成立标签都要有独立证据。

### 第四步：解决疑问，补齐核验材料

逐项处理机器复核队列，核查人工备注。已解决的片段取消“待复核”；仍无法解决的继续保留，不要为完成任务而消除警告。

确认 `F1 有害虚假信息` 时，在该片段“核验材料”中填写事实核查来源和解释。其他涉及授权、目的或上下文的判断，也应写明依据；不能只写“已查证”。

### 第五步：填写裁决说明，保存最终状态

在“裁决说明”中概括主要处理及依据。例如：“保留 95–99 秒 A1；取消缺乏严重伤情证据的 A4；补标 156–158 秒的击打动作。”

只有在两份人工均已提交、全片已核查、所有问题已处理后，才选择“已完成”或“确认无风险内容”，并确认顶部“已保存”。仍存疑时使用“需专家复核”，写清未解决项；这不是最终核验通过。

如果系统提示人工来源已变化，说明某位标注员在专家核验期间或之后修改了结果。请先备份当前专家草稿，再重新加载两份最新人工记录，对变化内容重新核查后保存。不要沿用过期结论。

专家不需要下载数据集或运行导出命令；最终数据汇总由管理员统一处理。

## 六、暂停工作、备份与交接

平时不需要逐条导出，Python 服务会将各人的记录及修订历史保存到本机磁盘。默认位置是 `.annotation-work/desktop-quality_review_20260914/annotations/你的代号/`。完成后，将自己的整个代号文件夹压缩交回负责人；目录以点开头，文件管理器可能需要开启“显示隐藏文件”。不要把它公开上传到 GitHub。**以下情况请使用顶部“备份本视频”**：保存失败、网络不稳定、出现版本冲突，或即将进行可能替换草稿的操作。

备份会下载当前视频的 JSON 文件。请保留原文件，并向负责人说明工作代号和视频编号；不要把它当作本机文件已经保存成功的证明，也不要公开上传。

暂时离开时，未完成的视频保持“进行中”，确认保存后再关闭页面。重新进入时可用左侧“未完成”筛选和视频编号搜索继续处理。结束工作时，确认保存后关闭网页，并回到终端按 Ctrl+C 停止服务。下次进入同一仓库目录、用同一代号运行即可继续。清理或删除仓库前，务必先把 `.annotation-work` 复制到安全位置。

## 七、遇到问题时怎么办？

| 现象 | 处理步骤 |
|---|---|
| 本地网页打不开 | 确认运行 Python 的终端没有关闭，复制它打印的完整地址；不要使用旧的临时公网链接 |
| 网页要求输入密码 | 你可能打开了旧在线入口。新版请运行 `python annotate.py`，使用它打印的本地地址 |
| 工作区代号不对 | 停止编辑，重新以正确的 `--annotator A1/A2/EXPERT` 启动，不要把结果写进他人目录 |
| 视频卡顿 | 暂停等待缓冲，检查网络，必要时降至正常倍速；不要跳过未看清部分后直接完成 |
| 黑屏、只有声音，或显示媒体缺失 | 记录视频编号和现象，联系负责人。需要提交问题时选择“需专家复核”，不要确认无风险 |
| 转写为 partial、缺少转写或转写明显不对 | 以实际音轨为准；缺失转写不等于无语音。若原音也无法核实，写明证据缺口并交专家 |
| 无法保存，提示标签、理由或时间不合法 | 按提示检查片段：起点小于终点、没有超出全片时长、标签/模态/理由齐全 |
| 不能保存“已完成” | 检查全片确认框、片段“待复核”、队列未处理项和视频结论是否一致；有疑问应选“需专家复核” |
| 保存失败或版本冲突 | 先“备份本视频”，不要立刻刷新；确认没有另一个标签页在使用同一工作目录和代号，联系负责人后再加载最新记录并核对 |

反馈问题时，请提供**自己的工作代号、视频编号、发生时间、操作步骤和报错截图**。截图尽量聚焦错误提示，避免夹带不必要的敏感画面。

## 八、容易出错的地方：提交前再核对一次

### 1. 不要让机器结果替你作决定

- **高置信度不等于正确。** 机器可能把轻伤夸大为重创，把普通争论当作辱骂，或把反驳歧视的话误判为歧视。无论置信度高低，都要回到原画面和原音判断。
- **没有候选不等于没有风险。** 模型可能漏掉某次动作，甚至只标出附近另一件事。要核对当前时间点真正发生了什么，不能以“其他地方已经标过同类”代替本段检查。
- **机器原始提示不一定随人工修改消失。** 删除右侧误报后，中间仍能看到原机器建议，这是为了保留参照，不表示删除失败。请以自己的事件列表和保存状态确认编辑结果。

### 2. 时间边界和标签范围要一起检查

| 容易犯的错误 | 正确处理 |
|---|---|
| 把 `01:35` 写成 `1.35` | 时间输入框单位是秒，应填写 `95` |
| 使用 2× 播放后把时间除以二 | 倍速不改变视频时间轴，按界面显示的原视频秒数填写 |
| 新建片段后忘记修改默认边界 | 新建只是建立草稿，必须重新检查实际起点和终点 |
| 把采访、准备动作和事后反应都框进风险 | 可多看上下文，但风险区间只保留使标签成立的完整语义单元 |
| 给整段打斗同时贴上所有相关标签 | 每类单独核实证据；若 A1 为 10–20 秒、A4 只在 15–17 秒成立，应分别建段，不把 A4 铺满 10–20 秒 |
| 为了让条数好看，把相邻段全部合并 | 只有同一风险语义连续时才合并；明显正常间隔应保留 |
| 原片出现过一次，回放就不再标 | 同一内容在视频里再次出现时，按新的实际时间位置标注 |

### 3. 分类时检查“成立条件”，不要凭场景联想

| 常见混淆 | 核对重点 |
|---|---|
| 擦伤、少量血迹 → A4 | 是否真的达到分类指南要求的重创或大量血液程度 |
| 性话题或性化内容 → B2 | 是否有受侵扰对象、侵扰行为及非自愿依据；自愿内容不能直接推成性侵害 |
| 提到某种身份 → C2 | 身份是否构成恶意攻击的依据；要区分直接歧视、转述、反驳和讽刺 |
| 语气激动、感叹词 → C1 | 是否确实针对对象进行侮辱或恐吓，而非口头禅或就事论事 |
| 持枪、警察追逐 → E1 | 是否另有取财、索财或故意毁损的明确证据 |
| 扑克牌、酒瓶出现 → D2 或 D1 | 是否分别满足财物下注/诱导，或物质滥用的必要条件 |
| 主张听起来可疑 → F1 | 是否有具体事实主张、证伪依据、传播立场与危害；证据不足时交专家 |
| 画面出现姓名或人脸 → F2 | 是否涉及非公开信息或侵入隐私，以及未经授权的依据 |

同一条证据不要机械叠加标签。例如同一句话的性侵扰、身份攻击和一般辱骂按分类指南处理优先级；不同证据独立成立时才保留多个标签。新闻、科普或影视的来源名称本身不能决定整片正负，要看具体片段实际呈现的内容与语境。

### 4. 分清三个不同层次的“复核”

- **片段的“待复核”勾选**：说明这条人工片段仍有证据疑问。解决后才取消；取消它不会替你填写其他信息。
- **机器待检查队列的处理选项**：说明你如何处理一条机器提示。选择“已补标”不会新建片段，选择“确认不成立”不会删除片段。
- **视频的“需专家复核”状态**：说明整条视频还有问题要交专家。请写明具体疑点，不能只改状态而不交代原因。

三者应相互一致。不能一边保留“仍存疑”或片段“待复核”，一边选择“已完成”；也不能通过随意勾选“已查看”来跳过实际检查。

### 5. 不要把“草稿保存”当作“任务完成”

“已保存”表示当前内容已由本机 Python 服务写入磁盘，**不代表视频已经标完**；视频仍可能是“进行中”。反过来，点选“已完成”但保存失败，也不算成功保存。请同时确认视频状态和保存状态。

尽量只开一个正在编辑的标签页。同一工作目录和代号在多个标签页或设备同时修改，可能产生冲突。出现冲突先备份，再核对最新记录；不要连续刷新，也不要让两个人共用一个工作代号。

专家选择某人的片段起稿后，还要重新检查自己的复核队列、全片确认、理由和裁决说明。起稿不会自动完成这些步骤；两份人工结果相同，也不意味着可以免去专家回看。

## 九、工作节奏与判定依据

请将[分类与边界判定指南](instructions.md)作为类别判断依据，将本文作为操作顺序参考。遇到规范未覆盖的问题，记录疑问并统一反馈，不自行创造新类别或修改定义。

连续工作不超过两小时，中途注意休息。看到让自己不适的内容时，可以暂停并联系负责人调整任务；不要为了赶进度而降低核查要求。
